# 通过 Pending IRP 实现 HIPS 与 EDR 日志不中断的完整范式

> 传统安全架构的血脉压制：**HIPS 拦截越高，EDR 越瞎**——因为 ETW 只会为"已完成"的操作产生事件。ZETA 在驱动层挂起 IRP，让 HIPS 在决策前主动把操作数据投喂给 EDR，从根本上终结这个架构级死锁。

---

## 问题：传统 HIPS 与 EDR 的底层冲突

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│   进程发起高危操作（写文件 / 改注册表）                          │
│       │                                                      │
│       ├── 传统 HIPS：拦截！立刻返回 ACCESS_DENIED              │
│       │         │                                            │
│       │         └── 操作从未实际发生                           │
│       │               │                                      │
│       │               └── ETW 不产生任何事件                   │
│       │                     │                                │
│       │                     └── EDR 完全"失明"                │
│       │                                                      │
│       └── 传统 HIPS：放行                                     │
│                 │                                            │
│                 └── ETW 终于有事件了                           │
│                       │                                      │
│                       └── EDR 看到了……但攻击已经发生了          │
│                                                              │
│   ═══════════════════════════════════════════════════════     │
│   致命结论：ETW 只记录"已完成"的操作。                         │
│   HIPS 越强 → 拒绝越多 → ETW 事件越少 → EDR 越眼瞎。           │
│   两个安全模块互相抵消，1+1<1。                                │
│   ═══════════════════════════════════════════════════════     │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

一个勒索软件往 `ProgramData` 写文件 + 改 `Run` 启动项，传统架构下：

| 操作 | HIPS | EDR |
|------|------|-----|
| 写 `malicious.sys` | 拒绝 | **不知道**（无 ETW 事件） |
| 改 `HKLM\...\Run` | 拒绝 | **不知道**（无 ETW 事件） |
| 进程被杀 | — | 只看到 `ProcessExit`，**不知道这进程干了什么** |

**EDR 的威胁日志是空的。排查人员只能猜。**

---

## 解决方案：HIPS 主动投喂 EDR

**核心思路**：在 HIPS 做决策之前，先把操作数据发给 EDR。

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│   进程发起高危操作                                             │
│       │                                                      │
│       ▼                                                      │
│   内核 Minifilter PreCallback                                 │
│       │                                                      │
│       ├─ 匹配保护规则                                         │
│       ├─ FltLockUserBuffer()                                 │
│       ├─ PendOperation()  ← 挂起 IRP，进程卡住                │
│       │                                                      │
│       ├─ SendMessageToUser(操作上下文)  ← ★ 关键：先发消息     │
│       │                                                      │
│       ▼                                                      │
│   ┌─────────────────────────────────────────────┐            │
│   │             用户态 ZETA                      │            │
│   │                                             │            │
│   │   ┌───────────┐          ┌──────────────┐   │            │
│   │   │   HIPS    │ ──投喂──→│     EDR      │   │            │
│   │   │           │  操作数据 │              │   │            │
│   │   │ 弹出决策   │          │ 评分 +20     │   │            │
│   │   │ 用户选择   │          │ 血缘追踪     │   │            │
│   │   │           │          │ 日志落盘     │   │            │
│   │   └─────┬─────┘          └──────────────┘   │            │
│   │         │                                   │            │
│   │         │  发命令给驱动                      │            │
│   └─────────┼───────────────────────────────────┘            │
│             │                                                │
│             ▼                                                │
│   驱动 FltCompletePendedPreOperation()                        │
│        ├─ 阻止 → STATUS_ACCESS_DENIED                         │
│        └─ 允许 → STATUS_SUCCESS                              │
│                                                              │
│   ═══════════════════════════════════════════════════         │
│   HIPS 允许还是拒绝？不重要。EDR 已经拿到日志了。               │
│   ═══════════════════════════════════════════════════         │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

执行同一次勒索软件攻击：

| 操作 | HIPS | ZETA EDR |
|------|------|----------|
| 写 `malicious.sys` | 挂起→用户拒绝 | **已记录**：路径/进程/PID/时间 |
| 改 `HKLM\...\Run` | 挂起→用户拒绝 | **已记录**：注册表路径/值 |
| 行为评分 | — | **自动累加**：两次高危 = +40 |
| 最终 | 进程被杀 | **完整日志**：每个操作都在 |

## 技术实现：Pending IRP 等于分布式事务

这不是"先记再干"那么简单。Windows 内核中，文件创建操作一旦完成，无法撤销。必须从架构层面解决：

```
IRP_MJ_CREATE 到达 Minifilter
        │
        ├─ 返回 FLT_PREOP_SUCCESS_NO_CALLBACK → 操作继续 → ETW 正常
        │               
        ├─ 返回 STATUS_ACCESS_DENIED         → 操作终止 → ETW 无事件 → EDR 瞎
        │
        └─ 返回 FLT_PREOP_PENDING  ← ZETA 的做法
                │
                ├─ 进程被阻塞（CreateFileW 卡住）
                ├─ 驱动通过 Filter Communication Port 发消息
                ├─ 用户态 HIPS 弹出弹窗的同时投喂 EDR
                ├─ EDR 评分、记录、血缘追踪，日志完全独立落盘
                │
                └─ 用户决策 or 30秒超时
                       │
                       ├─ FltCompletePendedPreOperation(SUCCESS)
                       └─ FltCompletePendedPreOperation(ACCESS_DENIED)
```

| 状态 | 传统 HIPS | ZETA |
|------|----------|------|
| 决策前 | 操作已拒绝/已放行 | **操作挂起，两可之中** |
| EDR 可见性 | 依赖 ETW | **HIPS 投喂，独立于 ETW** |
| 日志完整性 | 拒绝=无日志 | **100% 完整** |
| 超时 | 无/进程僵死 | **30秒自动拒绝** |

### 功能清单

**HIPS**：文件保护 · 注册表保护 · 勒索行为检测 · 银狐(SilverFox)检测 · BYOVD 驱动拦截 · 卷/磁盘保护

**EDR**：行为评分引擎 · 血缘追踪 · YARA 扫描 · 自动终止(85分) · 评分衰减(120s) · **日志不中断**

## 构建

```powershell
# 内核驱动
cd Plugins\Filter
msbuild ZETA_Driver.sln /t:Build /p:Configuration=Release /p:Platform=x64

# 用户态组件
cd CppLibs && mkdir build && cd build
cmake .. -G "Visual Studio 17 2022" -A x64
cmake --build . --config Release

# Qt UI
cd QtUI_DLL && mkdir build && cd build
cmake .. -G "Visual Studio 17 2022" -A x64
cmake --build . --config Release
```
